# ZValleyDashboard 前端页面主题风格适配 · 需求澄清

## 1. 一句话概述

在 ZValleyDashboard 现有前端脚手架（登录页 / 主框架布局 / 仪表盘首页 / 错误页 / 示例组件）上接入基于「苔 Moss」色板的浅色 / 深色 / 跟随系统三态主题能力，通过顶栏切换按钮手动切换并持久化偏好，使所有既有页面在任意主题模式下样式统一、对比度合规、首屏无闪烁，同时不新增功能模块、不改现有业务交互。

## 2. 背景与目标

### 2.1 背景

- 现有前端脚手架是 `Vue 3 + Element Plus + Pinia + Vite + UnoCSS` 初始化产物，登录页、侧栏、顶栏颜色均为硬编码（如侧栏 `#001529/#002140`、登录页蓝色渐变 `#1677ff→#69b1ff`、顶栏白色）。
- 全局样式仅在 `src/styles/variables.scss` 定义了尺寸变量（侧栏宽度、顶栏高度等），**未定义任何色板 CSS 变量**，未接入 `element-plus/theme-chalk/dark/css-vars.css`，页面仅能以浅色渲染。
- 模板与规范目录提供了「苔 Moss」主题 tokens（`knowledge/template/网页页面主题风格.md`），约定了主色、表面色、文本色、边框色、圆角、字号、字重在 `:root` 与 `[data-theme="dark"]` 下的值，以及"浅色默认 + `data-theme=dark` 暗色 + 跟随系统 `prefers-color-scheme`"的三态用法。
- 缺少主题切换入口与持久化机制，用户无法表达暗色偏好；若直接引入暗色样式，将出现首屏闪烁（FOUC）问题。

### 2.2 目标

1. 用户可以在顶栏通过一个图标按钮在"浅色 / 深色 / 跟随系统"三种主题模式间循环切换，并立即在当前页面生效。
2. 页面在浅色与深色模式下均有良好对比度：主色、表面（画布 / 卡片 / 凹陷区）、文本（一级 / 二级 / 三级）、边框（默认 / 强化）、状态色均使用「苔 Moss」tokens，不出现硬编码颜色导致的"亮块 / 黑块"。
3. Element Plus 组件（按钮、卡片、菜单、表单、下拉、面包屑、消息、对话框、头像、统计数等）的暗色表现通过官方 dark css-vars 层叠，并被 moss 主色语义变量覆盖，保证视觉一致。
4. 用户的主题偏好持久化在 `localStorage`（复用现有 `pinia-plugin-persistedstate` 机制，与 `locale` / `sidebarCollapsed` 同存于 `zvalley_dashboard_app`）；刷新、重新打开浏览器仍然保留。
5. 首屏加载阶段在 Vue 挂载前同步应用主题，避免"先白后黑 / 先黑后白"的闪烁；主题切换时有平滑的 CSS 颜色过渡（约 0.2s）。

### 2.3 不做（Non-Goals）

| 编号 | 不做的内容 | 原因 / 后续规划 |
|------|------------|------------------|
| NG-01 | 不做浅色 / 深色之外的第三套主题（高对比度、节日皮肤、企业定制品牌色等） | 本次以落地模板「苔 Moss」为目标；多品牌 / 多皮肤属于后续 Design Token 体系建设范畴。 |
| NG-02 | 不重构现有组件为完整 Design Token 体系（不拆 @tokens、不引入 CSS-in-JS、不换主题框架） | 仅在 `src/styles/` 下集中定义 CSS 变量并在既有 scoped 样式中替换硬编码值，控制本次改动范围。 |
| NG-03 | 不处理 RTL、字号缩放、色盲友好等其它可访问性主题能力 | 可访问性是独立议题，后续专项迭代。 |
| NG-04 | 不做云端 / 后端用户偏好同步，不接账号级主题设置接口 | 偏好仅存 `localStorage`；多端同步需后端与账号体系支持，不在本次前端脚手架改造范围。 |
| NG-05 | 不新增页面、路由、接口或业务功能模块，不改动现有业务交互流程 | 本次仅为视觉样式适配；登录、仪表盘统计、权限指令、国际化、语言切换、侧栏折叠等既有交互行为保持不变。 |
| NG-06 | 不迁移原型目录 `prototype/knowledge-base/` 的页面主题 | 该目录为知识库工作流原型链路产物，有独立的 AGENTS.md 约束，不在本前端脚手架主题改造范围内。 |

## 3. 需求详情

### 3.1 用户场景

| 场景 ID | 谁 | 在什么上下文下用 | 期望结果 |
|---------|-----|------------------|----------|
| S-01 | 首次访问的访客 | 打开登录页 | 页面默认以跟随系统模式呈现（或按默认值），渐变背景与卡片在对应主题下对比度达标；可在登录页右上角切换主题。 |
| S-02 | 偏好暗色的已登录用户 | 进入仪表盘首页 | 切换到深色后，侧栏、顶栏、统计卡片、Demo 卡片、按钮、下拉、面包屑均以 moss 暗色 tokens 渲染，无突兀亮色；刷新后仍保持深色。 |
| S-03 | 选择"跟随系统"的用户 | 系统在白天 / 夜间自动切换明暗模式 | 当 OS 主题变更时，页面无需刷新即可跟随切换；手动切换后若再次切回"跟随系统"，则恢复跟随系统。 |
| S-04 | 用户访问无权限 / 不存在页面 | 跳转到 403 / 404 错误页 | 错误页在当前主题下背景、插画占位、文案、按钮均配色协调，不会出现默认白底黑字硬编码。 |
| S-05 | 开发者查看示例组件 | 访问 HelloWorld 示例组件（若存在对应路由） | 示例组件的文本、按钮、代码块、链接均适配主题，可作为主题接入正确性的最小回归样本。 |

### 3.2 用户路径（主流程）

1. 用户首次打开站点 → 进入登录页 → 页面以默认主题"跟随系统"渲染（见 OQ-1） → 可在右上角通过主题按钮切换。
2. 用户点击主题按钮 → 主题模式按"浅色 → 深色 → 跟随系统 → 浅色"循环切换（三态方案） → 页面颜色 0.2s 内平滑过渡 → 当前模式写入 localStorage。
3. 用户登录 → 进入 DefaultLayout（侧栏 + 顶栏 + 内容区） → 顶栏仍展示主题按钮 → 侧栏、顶栏、面包屑、头像下拉、内容区底色随主题变化。
4. 用户访问仪表盘 → 统计卡片、Demo 卡片、按钮、消息提示在当前主题下正常显示 → `el-card` 阴影/边框对比度合理。
5. 用户刷新页面 / 关闭后重开 → `index.html` 内联脚本在 Vue 挂载前读取 localStorage / prefers-color-scheme → 立即在 `<html>` 根节点设置正确的主题标记 → 用户看到的首帧即为目标主题，无闪烁。
6. （异常/回退）用户访问不存在页面 → 渲染 404 错误页，主题按钮仍可使用并即时切换错误页主题。

### 3.3 主题模式定义

| 模式 | 标识 | html 根标记 | 生效条件 |
|------|------|-------------|----------|
| 浅色 | `light` | `data-theme="light"`，无 `.dark` class | 用户显式选择浅色；或"跟随系统"且 `prefers-color-scheme: light` |
| 深色 | `dark` | `data-theme="dark"` + Element Plus 要求的 `.dark` class | 用户显式选择深色；或"跟随系统"且 `prefers-color-scheme: dark` |
| 跟随系统 | `system` | 由运行时根据 `prefers-color-scheme` 动态切换为上述之一 | 用户显式选择跟随系统，监听 `matchMedia('(prefers-color-scheme: dark)')` 的 `change` 事件 |

> 注：用户选择存储的是**模式**（light / dark / system），而非最终生效的明暗值；"跟随系统"模式下最终明暗由 OS 决定。

### 3.4 产品规则（TR-*）

**展示规则**

- TR-01：顶栏右侧（语言切换下拉旁）必须存在一个主题切换图标按钮。浅色模式下显示"月亮"图标（表示点击切到深色），深色模式下显示"太阳"图标（表示点击切到浅色）；"跟随系统"模式下显示"自动/显示器"图标。点击行为见 TR-05。
- TR-02：首次访问（localStorage 无主题偏好时）默认模式为 **"跟随系统"**（见 OQ-1，可在 Spec 阶段调整为"浅色"）。
- TR-03：侧栏背景、logo 区背景、菜单项文字 / 激活态、顶栏背景与底部分割线、面包屑文字、头像下拉菜单背景、主内容区背景、卡片背景与边框、统计数字标题与值、按钮颜色、输入框、Toast/MessageBox、代码块（`<code>`）必须全部来自 CSS 变量，不得保留硬编码十六进制颜色（如 `#001529`、`#1677ff`、`#fff`、`#000`）作为最终色值。
- TR-04：所有页面（登录页 / DefaultLayout / dashboard / error/* / HelloWorld）均须在浅、深两套 tokens 下被验证覆盖；登录页的渐变背景需要为暗色模式单独定义深色渐变（基于 moss 深色表面色 + 主色暗化）。

**交互与生效规则**

- TR-05：点击主题按钮按 `light → dark → system → light` 循环切换；每次点击立即生效，不弹二次确认、不需要刷新。
- TR-06：用户在 `system` 模式下若 OS 主题在浏览过程中改变，页面应**自动**跟随切换（通过 `window.matchMedia('(prefers-color-scheme: dark)').addEventListener('change', ...)`），无需用户点击按钮。
- TR-07：主题切换时有 0.2s 左右的 `background-color / color / border-color / box-shadow` 过渡，覆盖 `body`、侧栏、顶栏、卡片、按钮等主要元素；图片、图表等不参与颜色过渡，避免闪烁。
- TR-08：主题偏好通过现有 pinia persistedstate 存储到 `localStorage` 的 `zvalley_dashboard_app` 键下（新增 `theme: 'light' | 'dark' | 'system'` 字段）；持久化路径在现有 `paths: ['sidebarCollapsed', 'locale']` 基础上追加 `'theme'`。

**兼容与降级规则**

- TR-09：首屏防闪烁：在 `index.html` 的 `<head>` 中内联一段同步 JS（IIFE，无依赖），在样式与 Vue 挂载前读取 localStorage 中的主题偏好 → 若为 `light` / `dark` 直接在 `<html>` 上设置对应标记；若为 `system` 或无值，读取 `prefers-color-scheme` 并设置；该脚本需与运行时逻辑保持同源（同一个 key、同一套判定）。
- TR-10：Element Plus 暗色接入方式为：在暗色生效期间给 `<html>` 加 `.dark` class 并 `import 'element-plus/theme-chalk/dark/css-vars.css'`；再在 `[data-theme="dark"]`（或 `html.dark`）下用 moss 主色覆盖 Element Plus 的 `--el-color-primary*` 系列变量，使按钮、链接、选中态呈现 moss 绿而非 Element Plus 默认蓝。
- TR-11：浏览器不支持 `matchMedia` 或 `prefers-color-scheme` 时（极旧浏览器），`system` 模式降级为浅色。
- TR-12：不支持 JS 时（极低概率场景）页面以 `:root` 默认浅色 tokens 呈现，不影响可读性。

**权限 / 可见性规则**

- TR-13：主题切换按钮对所有用户可见，不依赖登录状态（登录页也要有），不依赖权限（`v-permission` 不控制它）。登录页使用 BlankLayout，需要在 BlankLayout / 登录页自身提供同一主题按钮或共享一个主题切换组件。

**保持不变**

- TR-14：登录流程、表单校验、国际化（中文 / English 切换）、侧栏折叠、路由跳转、仪表盘统计接口调用、`v-permission` 指令、NProgress 进度条等现有行为与视觉位置必须保持可用；主题适配不得改变文字内容、布局尺寸、控件可点击区域、hover/active 逻辑。

### 3.5 状态与反馈

| 状态 | 用户可感知结果 |
|------|----------------|
| 切换成功 | 页面所有可视区域在 0.2s 内过渡到目标主题；按钮图标立即更新为对应模式图标。 |
| 切换失败 | 主题切换是纯前端无网络操作，预期不会失败；如 localStorage 不可用（隐私模式），本次会话内仍可切换，仅不持久化，下一次打开回默认值，无需提示。 |
| 空态 / 无数据 | 不涉及数据空态变化，沿用现有各页面空态文案。 |
| 无权限 / 403 / 404 | 错误页底色、插画占位（若有）、文案、返回按钮均随主题变化，按钮仍可点击。 |
| 异常 | 浏览器不支持 CSS 变量的环境（IE 等）不在兼容范围；其他现代浏览器下主题能力是增强项，降级到 `:root` 默认浅色仍可读。 |
| 保持不变 | 登录成功 / 失败 Toast 文案与触发时机不变；国际化切换逻辑不变；侧栏折叠状态逻辑不变。 |

### 3.6 关键文案

| 位置 | 文案 | 备注 |
|------|------|------|
| 主题按钮 `title` / `aria-label` | 浅色模式下："切换到深色模式"；深色模式下："切换到跟随系统"；跟随系统下："切换到浅色模式"（对应点击路径 light→dark→system→light） | 最终 tooltip 文案可在编码阶段根据图标语义微调，但需提供 aria-label 供无障碍访问。 |
| 主题按钮 tooltip | 若采用 `el-tooltip`，文案与 aria-label 一致 | i18n 需要补充 `app.themeLight` / `app.themeDark` / `app.themeSystem` 三个 key（中文："浅色模式" / "深色模式" / "跟随系统"）以及切换提示模板。 |

### 3.7 关键表现要求

- **色板来源**：必须直接使用 `knowledge/template/网页页面主题风格.md` 中「苔 Moss」的 tokens（`--moss-primary / --moss-primary-soft / --moss-ink / --moss-accent / --moss-clay / --moss-stone / --moss-mist / --surface-canvas / --surface-card / --surface-sunken / --text-primary / --text-secondary / --text-tertiary / --text-on-primary / --border-default / --border-strong / --radius-* / --font-* / --text-* / --leading-* / --weight-*`），暗色模式使用该模板 `[data-theme="dark"]` 下的色值。
- **圆角、字号、字重、行距**：优先复用 moss tokens 中已定义值，避免出现与模板不一致的 4px 圆角或 14px/16px 新字号基线。
- **Element Plus 主色覆盖**：在暗色与浅色下均用 moss 主色覆盖 `--el-color-primary` 及其 light/dark 分级（`--el-color-primary-light-1~9`、`--el-color-primary-dark-2`），确保 `type="primary"` 按钮、链接色、focus ring 统一为 moss 绿而非 EP 默认蓝。
- **侧栏改造**：现状侧栏硬编码 `#001529`，改造后不再保留深海军蓝，浅色模式下使用 moss 色系的"深色侧栏"视觉（基于 `--moss-ink` / `--moss-primary-soft` 层级），暗色模式下使用 `--surface-card` / `--surface-sunken` 层级；具体对比度在编码阶段验证（见 OQ-2）。
- **登录页背景**：替换蓝色渐变。浅色使用 `--moss-mist → --moss-primary-soft` 的柔和渐变；暗色使用 `--surface-canvas → --moss-primary-soft(暗)` 的低饱和渐变，避免高饱和蓝光。
- **对比度要求**：正文与背景对比度不低于 WCAG AA（4.5:1），次要文字不低于 3:1（实现后由开发阶段自查）。
- **过渡范围**：只对颜色类属性加 transition，不对 `width`、`transform` 等布局属性加全局过渡，避免影响现有侧栏折叠动画。

## 4. 约束限制

| 类别 | 约束 |
|------|------|
| 技术栈 | 保持现有 Vue 3 + Element Plus + Pinia + UnoCSS + Vite + SCSS；不引入新的 CSS 框架、不换状态管理、不加 CSS-in-JS。 |
| 样式组织 | 新增主题相关 CSS 变量集中到 `src/styles/` 下一个新文件（建议 `theme.scss`），在 `index.scss` 中 import；moss 色板变量放 `:root`，暗色覆盖放 `html.dark, [data-theme="dark"]` 选择器下以兼容 Element Plus。 |
| 状态管理 | 新增 `theme` 状态放在现有 `useAppStore`（`src/store/modules/app.ts`），与 `locale` / `sidebarCollapsed` 并列；提供 `setTheme(mode)` action；persist `paths` 追加 `'theme'`。 |
| 首屏脚本 | 内联脚本放在 `index.html` `<head>`，必须在主样式之后、`#app` div 之前、主模块脚本之前执行；脚本体积尽量小于 1KB。 |
| i18n | 在现有 `src/locales/` 中文与英文包里补充主题相关文案 key，原有 key 不重命名、不删除。 |
| 组件改造 | 现有 `.vue` 文件中的硬编码内联样式（如 `background-color="#001529"`、`style="background: linear-gradient(...)"`）需迁移到 `<style scoped lang="scss">` 或 `<style>` 块中并使用 CSS 变量；禁止在 template 内继续写死颜色。 |
| 兼容性 | 现代浏览器（Chrome/Edge/Firefox/Safari 最新两个大版本）；不要求兼容 IE；`prefers-color-scheme` 不支持时 system 降级浅色（TR-11）。 |
| 性能 | 不增加首屏可感知延迟；CSS 变量切换本身是同步的，内联脚本执行时间应远小于一帧（< 10ms）。 |
| 稳定性 | 主题切换过程不触发路由刷新、不触发组件重新挂载、不丢失表单输入状态。 |
| 测试 | 对 `useAppStore` 的 theme 相关 getter/action 补充或扩展 `src/store/__tests__/` 下的单测；不强制 E2E（本仓库 E2E 是知识库原型链路）。 |
| 代码风格 | 遵循仓库现有 ESLint / Stylelint / Prettier / Conventional Commits 约定；stylelint 新增规则需能通过（不得出现未使用变量）。 |
| 范围禁区 | 不改动 `prototype/`、`e2e/`、`docs/requirements/知识库系统-*`；不改动既有 API 调用、路由 meta、权限指令实现；不升级依赖大版本。 |

## 5. 验收标准

- [主流程 · 浅 ↔ 深切换] 在已登录状态下，用户点击顶栏主题按钮，页面应在 0.2s 内平滑在浅色 / 深色之间切换；侧栏背景、顶栏背景、卡片、按钮、文字颜色同步变化，不出现部分区域未切换（白块 / 黑块）。
- [主流程 · 三态循环] 连续点击主题按钮，模式应按 `light → dark → system → light` 循环；按钮图标与 tooltip 文案同步更新。
- [主流程 · 跟随系统] 选择"跟随系统"后，手动改变操作系统主题（或通过 DevTools 切换 `prefers-color-scheme`），页面应自动在浅色 / 深色之间切换，无需刷新、无需再次点击按钮。
- [持久化] 切换到非默认主题后刷新页面（F5 / Ctrl+R），首帧即为目标主题，无"先白后黑"闪烁；关闭浏览器重新打开仍保持上次选择的模式。
- [FOUC 防闪烁] 清空 localStorage 后分别在系统浅色 / 深色模式下硬刷新（Ctrl+Shift+R），首屏不应出现与目标主题相反的底色闪烁。
- [登录页] 登录页渐变背景、卡片、表单、按钮、下拉在浅 / 深主题下颜色协调，不出现原蓝色渐变硬编码；登录页右上角主题按钮可用，切换即时生效。
- [DefaultLayout] 侧栏（含 logo 区、菜单项文字 / hover / active 态）、顶栏（含折叠按钮、面包屑、语言下拉、头像下拉、分割线、阴影）在两种主题下对比度达标、无硬编码色值残留。
- [仪表盘] 欢迎标题、4 个统计卡片（el-card + el-statistic）、Demo 卡片、按钮（primary / success / default）、`<code>` 提示文本、Toast / Message 弹窗在两种主题下显示正常，无白色卡片浮在深色背景上无边界、或深色文字压在深色背景上的情况。
- [错误页] 403 / 404 页面在两种主题下背景、文案、按钮配色协调；主题按钮可用。
- [Element Plus 主色] 所有 `type="primary"` 的按钮、链接色、focus 边框、菜单激活态在浅色 / 深色下均呈现 moss 绿（约 `#5A8A3C` / `#97C459` 量级），而非 Element Plus 默认蓝 `#409EFF`。
- [HelloWorld / 示例组件] 示例组件内的文本、按钮、代码块在两种主题下可阅读；若示例组件包含硬编码色值，需替换为变量。
- [i18n] 在中文 / English 语言下，主题按钮 tooltip / aria-label 文案均正确显示对应语言。
- [不影响既有能力] 登录 / 登出、表单校验、语言切换、侧栏折叠、路由跳转、统计接口调用成功 / 失败 Toast、admin 权限按钮显示逻辑、NProgress 进度条颜色在主题切换前后均保持原有功能正常，无回归。
- [无第三方新依赖] `pnpm-lock.yaml` 中除 Element Plus 已自带的 `theme-chalk/dark/css-vars.css` 外，不新增与主题相关的第三方依赖（不引 `vueuse/useColorMode`、`element-plus/theme-chalk/src/dark` 源码、不引 unocss-preset-theme 等，均以原生 CSS 变量 + Pinia + 一小段 matchMedia 实现）。
- [代码规范] 运行 `pnpm lint` 不新增 ESLint / Stylelint 错误；`pnpm type-check` 通过。

## 7. 推断项（基于现有惯例推断，已标注）

- **INFER-01**：主题状态放 `useAppStore` 而非新 store —— 与现有 `locale`、`sidebarCollapsed` 同属"应用级 UI 偏好"，符合 pinia 模块划分惯例。
- **INFER-02**：持久化 key 与路径追加在现有 `zvalley_dashboard_app` 的 `paths` 数组 —— 避免新增 localStorage key 增加管理成本。
- **INFER-03**：登录页的主题入口放在 `BlankLayout.vue`（与 DefaultLayout 同一位置）或登录页自身 header —— 因为登录页不走 DefaultLayout，必须提供同等切换能力，具体落点在编码阶段视 BlankLayout 现有结构决定，但要保证登录页可切换。
- **INFER-04**：NProgress 进度条颜色跟随主题（由 `src/styles/nprogress.scss` 内的变量改为读取 CSS 变量或在两种主题下分别覆盖），避免进度条颜色在暗色下刺眼。
- **INFER-05**：错误页 403/404 若使用 BlankLayout，主题按钮随 BlankLayout 一并生效；若错误页为独立布局，则由其自身提供主题按钮。
