# Review Summary

- 本次需求: 在 ZValleyDashboard 中交付一版「知识库系统」可交互高保真原型（HTML），覆盖知识文档创建/编辑、检索与筛选、模板复用主流程及主要异常状态。
- 需求类型: UX / frontend（原型交付）；不涉及生产后端、公开 API、埋点、权限体系。
- 变更面: UX Design（知识库入口、文档列表、文档详情、文档编辑、模板选择、检索与筛选、空态/错误态）；不涉及: Backend/Data、API Design、Metrics、Permission/Security、Audit 与统计；待确认: 文档编辑器类型、文档删除/版本管理、分类层级、多知识库形态。
- 变更面判断依据: 需求澄清文档（用户经交互卡片确认"画原型就够了"、明确不做多租户与权限体系）；仓库 zfWan/ZvalleyDashboard@ab516a3 仅含 init README 与需求澄清文档，无既有 ZValleyDashboard 模块代码可引用，故未展开与既有模块的集成范围。
- 差异判断: 产品形态差异：涉及——本次交付为独立可交互 HTML 原型，与生产产品形态不同，原型不含鉴权、后端与真实数据持久化；站点差异：不涉及；环境差异：不涉及；版本差异：不涉及（基于 ab516a3 基线）。
- 本次变更关键信息:
  - 新增知识库入口与三大主流程（创建文档 / 检索浏览 / 模板复用）的原型页面与交互规则。
  - 范围决策：本次仅交付原型，不做权限/多租户、生产后端、审计统计、与既有模块深度集成（仅导航入口示意）。
  - 风险/待确认：编辑器能力、文档删除与版本管理、分类层级、多知识库形态等以评审确认为准，默认值见 Open Questions。
- Review 重点:
  - scope：核对任务描述中的 5 大能力建议项与本次原型范围的取舍是否符合评审意见。
  - REQs：主流程 A/B/C 与异常状态的验收是否可测试。
  - 产品形态差异：原型与生产实现的边界是否清晰。

# 5. 功能需求

## REQ-001: 知识库入口与导航

**User Story**
> As a 用户, I want 从主导航进入知识库, so that 快速访问知识沉淀内容。

**Priority**: P0

**需求描述**
主导航提供「知识库」入口，点击后进入知识库首页（文档列表视图）。原型阶段入口仅作导航示意，不与其他模块联动。

**Acceptance Requirements**
- **REQ-001.1**: The system **shall** 在主导航中提供「知识库」入口。
- **REQ-001.2**: **When** 用户点击「知识库」入口, the system **shall** 展示知识库首页（文档列表）。
- **REQ-001.3**: **If** 原型加载异常, **then** the system **shall** 展示错误提示并可重试（见 REQ-008）。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 点击主导航「知识库」 | 跳转至知识库首页（PAGE-001） |

**关联埋点**: 无（原型不埋点）
**实现映射**: Design §4.1, Tasks 见下游任务拆分

---

## REQ-002: 分类创建与归属

**User Story**
> As a 用户, I want 按分类组织文档, so that 按主题沉淀与浏览知识。

**Priority**: P1（推断）

**需求描述**
原型采用一级分类结构（推断，层级见 OQ-004）：用户可创建分类；新建文档时必须选择分类，未选择时使用默认分类。

**Acceptance Requirements**
- **REQ-002.1**: The system **shall** 支持用户创建分类。
- **REQ-002.2**: **When** 用户新建文档且未选择分类, the system **shall** 将该文档归属默认分类。
- **REQ-002.3**: **If** 当前不存在任何分类, **then** the system **shall** 展示引导（创建分类或使用默认分类）并允许继续新建文档。

**Gherkin**
```gherkin
Scenario: 无分类时新建文档
  Given 知识库中没有任何分类
  When 用户点击「新建文档」并保存
  Then 文档归属默认分类并出现在文档列表中
```

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 创建分类并命名 | 新分类出现在分类列表 / 筛选项中 |
| 2 | 新建文档不选分类直接保存 | 文档归属默认分类 |

**关联埋点**: 无
**实现映射**: Design §4.2 PAGE-001, §6 FIELD-004

## REQ-003: 新建文档（空白 / 模板）

**User Story**
> As a 用户, I want 选择模板或空白创建文档, so that 快速产出结构化内容。

**Priority**: P0

**需求描述**
用户点击「新建文档」后，可空白创建或从系统预置模板中选择；选择模板后编辑器预填充模板内容（规则 3），用户修改后保存。

**Acceptance Requirements**
- **REQ-003.1**: The system **shall** 在新建入口提供「空白创建」与「选择模板」两种方式。
- **REQ-003.2**: **When** 用户选择某个模板, the system **shall** 将模板内容预填充到编辑器。
- **REQ-003.3**: **When** 用户保存新文档, the system **shall** 将该文档展示在对应分类列表中并使其可被检索。
- **REQ-003.4**: **If** 标题为空或必填字段缺失, **then** the system **shall** 阻止保存并提示校验信息（字段规则见 §6）。

**Gherkin**
```gherkin
Scenario: 基于模板新建文档
  Given 系统存在预置模板 T
  When 用户点击「新建文档」并选择模板 T
  Then 编辑器预填充模板 T 的内容
  When 用户补充标题与正文并保存
  Then 文档出现在对应分类列表并可被检索
```

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 点击「新建文档」 | 展示模板选择（PAGE-004） |
| 2 | 选择模板或「空白创建」 | 进入编辑页（PAGE-003）并预填充模板内容（如选择模板） |
| 3 | 填写并保存 | 校验通过后保存成功，返回列表 / 详情 |

**关联埋点**: 无
**实现映射**: Design §4.2 PAGE-003 / PAGE-004, §6 FIELD-001/002/005

## REQ-004: 文档编辑与保存

**User Story**
> As a 用户, I want 编辑文档并保存, so that 持续维护知识内容。

**Priority**: P0

**需求描述**
支持修改文档标题、正文、标签、分类并保存。原型无草稿 / 发布区分，保存即生效（推断）。

**Acceptance Requirements**
- **REQ-004.1**: The system **shall** 支持修改文档的标题、正文、标签与分类并保存。
- **REQ-004.2**: **When** 保存成功, the system **shall** 展示成功提示，并将最新内容反映到列表与详情页。
- **REQ-004.3**: **If** 保存失败, **then** the system **shall** 展示错误提示、允许用户重试，且不丢失已输入内容。

**Gherkin**
```gherkin
Scenario: 保存失败可重试且输入不丢失
  Given 用户在编辑页已输入标题与正文
  When 保存失败
  Then 展示错误提示且编辑页内容保持不变
  When 用户重试保存
  Then 保存成功并展示成功提示
```

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 打开编辑页（新建 / 编辑） | 展示可编辑表单（标题、正文、标签、分类） |
| 2 | 修改并点击保存 | 校验、保存、展示成功 / 失败反馈 |

**关联埋点**: 无
**实现映射**: Design §4.2 PAGE-003, §6, §7

## REQ-005: 文档查看与删除

**User Story**
> As a 用户, I want 查看文档详情, so that 阅读与复用知识内容。

**Priority**: P1

**需求描述**
用户点击列表条目进入详情页，查看标题、正文、标签与分类。删除能力范围待确认（见 OQ-003），本规格默认原型提供删除入口与二次确认，不做恢复 / 回收站。

**Acceptance Requirements**
- **REQ-005.1**: The system **shall** 在用户点击文档条目时展示该文档详情（标题、正文、标签、分类）。
- **REQ-005.2**: **When** 用户执行删除（范围待确认）, the system **shall** 在删除前要求二次确认。
- **REQ-005.3**: **If** 删除确认后, **then** the system **shall** 从列表与检索结果中移除该文档。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 点击列表条目 | 打开详情页（PAGE-002） |
| 2 | 点击「删除」并确认（如实现） | 文档被移除并返回列表 |

**关联埋点**: 无
**实现映射**: Design §4.2 PAGE-002

## REQ-006: 全文检索与筛选

**User Story**
> As a 用户, I want 按关键词检索并按分类 / 标签过滤, so that 快速找到目标文档。

**Priority**: P0

**需求描述**
原型首页提供搜索框；关键词匹配文档标题、正文与标签（规则 2，推断），不区分大小写；检索结果支持按分类 / 标签过滤。检索触发交互（实时 / 提交式）见 OQ-006。

**Acceptance Requirements**
- **REQ-006.1**: The system **shall** 支持输入关键词检索文档，匹配范围包含标题、正文与标签。
- **REQ-006.2**: **When** 用户输入关键词并触发检索, the system **shall** 返回匹配文档列表。
- **REQ-006.3**: The system **shall** 支持在检索结果上按分类、标签过滤。
- **REQ-006.4**: **If** 无匹配结果, **then** the system **shall** 展示空态并提供「清除筛选」与「新建文档」引导。

**Gherkin**
```gherkin
Scenario: 按标签过滤检索结果
  Given 用户已输入关键词 K 并获得结果列表
  When 用户选择标签 T 过滤
  Then 列表仅展示同时匹配关键词 K 且包含标签 T 的文档
  When 无匹配文档
  Then 展示无结果空态与「清除筛选」引导
```

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 在搜索框输入关键词 | 触发检索（触发方式见 OQ-006） |
| 2 | 选择分类 / 标签筛选项 | 列表按条件过滤 |
| 3 | 点击「清除筛选」 | 恢复全量列表 |

**关联埋点**: 无
**实现映射**: Design §4.2 PAGE-001, §6 FIELD-003/004

## REQ-007: 标签管理

**User Story**
> As a 用户, I want 为文档添加标签, so that 按标签检索与过滤。

**Priority**: P1（推断）

**需求描述**
编辑文档时可添加 / 移除标签；标签作为检索与过滤维度（推断）。

**Acceptance Requirements**
- **REQ-007.1**: The system **shall** 支持为文档添加标签。
- **REQ-007.2**: The system **shall** 支持移除文档标签。
- **REQ-007.3**: **When** 文档带有标签, the system **shall** 使该标签可被检索与过滤（见 REQ-006）。

| 1 | 编辑页添加标签 | 标签随文档保存 |
| 2 | 首页按标签筛选 | 展示带该标签的文档 |

**关联埋点**: 无
**实现映射**: Design §4.2 PAGE-001 / PAGE-003, §6 FIELD-003

## REQ-008: 状态与反馈（空态 / 加载 / 错误）

**User Story**
> As a 用户, I want 在任何状态下获得清晰反馈, so that 理解系统状态并采取下一步。

**Priority**: P0

**需求描述**
覆盖知识库无文档、检索无结果、加载中、加载 / 网络异常等状态；权限不足状态本次不涉及（NG-001）。

**Acceptance Requirements**
- **REQ-008.1**: **If** 知识库无任何文档, **then** the system **shall** 展示空态引导（「暂无文档」+「新建文档」入口）。
- **REQ-008.2**: **If** 检索无结果, **then** the system **shall** 展示无结果空态并提供「清除筛选」与「新建文档」引导。
- **REQ-008.3**: **If** 列表或页面加载中, **then** the system **shall** 展示加载中状态。
- **REQ-008.4**: **If** 加载或网络异常, **then** the system **shall** 展示错误提示并提供重试入口。
- **REQ-008.5**: The system **shall** 在原型中不呈现权限相关状态或交互（权限体系为 Non-Goal）。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 进入空知识库 | 展示空态与新建入口 |
| 2 | 检索无结果 | 展示空态与清除筛选 / 新建引导 |
| 3 | 网络异常时点击重试 | 重新加载 |

**关联埋点**: 无
**实现映射**: Design §4.2 PAGE-005, §7
